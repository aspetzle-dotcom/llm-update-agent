Large language models

An LLM is a transformer network trained to do one thing extremely well: predict the next token. Almost everything else it can do grows out of that.

The core idea

Give the model some text and it outputs a probability for every possible next token. Pick one, add it to the text, and repeat. That loop, run thousands of times, writes essays, code and answers. To get good at predicting the next word across the whole internet, a model has to pick up grammar, facts, reasoning patterns and style along the way.

  1. Text“The cat sat on the”
  2. Tokenssplit into pieces with IDs
  3. Embeddingseach ID becomes a vector
  4. Transformer layersattention + MLPs, dozens of times
  5. Next-token probabilities“mat” 41%, “floor” 22%…

Tokens

Models do not read letters or whole words. They read tokens: common words get a single token, while rare words are split into pieces. Tokenizers such as BPE are learned from huge amounts of text. In English, one token is roughly ¾ of a word.

This is a simplified tokenizer with a tiny vocabulary, for illustration. Real ones have 50,000 to 200,000+ tokens, so they split text less.

Tokens explain several quirks: pricing and context windows are counted in tokens, and models can struggle to count the letters in a word because they never see the individual letters.

Embeddings: meaning as position

Each token ID is turned into a long list of numbers, an embedding. Training arranges these so that related meanings end up near each other, and directions in the space can carry meaning.

Positions here are hand-placed to show the idea. Real embeddings have hundreds to thousands of dimensions.

The famous example: the arrow from man to woman is roughly the same as the arrow from king to queen. Embeddings also power semantic search and RAG, by finding passages whose vectors are close to a question's vector.

Attention

The breakthrough of the transformer (2017) is self-attention: every token decides how much to “look at” every earlier token and pulls in information from them. That is how the model works out that it refers to animal in one sentence and to street in another.

A model has many attention heads per layer, each specialising in a different kind of relationship, and dozens of layers. Each row of the grid adds up to 100%. Future tokens are masked, so the model cannot peek at the word it is meant to predict.

Generating text: temperature, top-k and top-p

The model gives probabilities; a sampling strategy picks the actual token.

  • Temperature sharpens (below 1) or flattens (above 1) the distribution. Near 0 the model almost always picks the top token: predictable. High values give more variety and more mistakes.
  • Top-k keeps only the k most likely tokens.
  • Top-p (nucleus sampling) keeps the smallest set of tokens whose probabilities add up to p.

How LLMs are trained

  1. PretrainingPredict the next token on trillions of tokens of text and code. Weeks on thousands of GPUs.
  2. Supervised fine-tuningLearn from curated examples of good instructions and answers.
  3. Preference tuningRLHF, DPO or similar: learn which of two answers people (or a reward model) prefer.
  4. RL for reasoningReward correct final answers on maths, code and tasks so the model learns to think step by step.
  5. Evaluation and safetyBenchmarks, red-teaming and policy testing before release.

Scaling laws describe how loss falls predictably as you add parameters, data and compute. That is why labs keep building bigger clusters. Much recent progress also comes from better data, longer training, and spending more compute at answer time (reasoning or test-time compute).

Limits and risks

  • Hallucination: fluent, confident and wrong. Check claims against sources, which is exactly why this app quotes the source text.
  • Knowledge cutoff: a model only knows its training data unless you give it fresh context.
  • Context limits: long inputs cost more, and details in the middle can be missed.
  • Prompt injection: text the model reads (web pages, emails) can try to hijack its instructions.
  • Bias: models absorb biases present in their training data.
  • Cost and latency: bigger models are slower and more expensive per token.

Glossary for the updates

Terms that show up often in the Updates feed:

InferenceRunning a trained model to get outputs (as opposed to training it).
KV cacheSaved attention keys and values from earlier tokens, so generation does not recompute them.
vLLM, llama.cppPopular open-source engines for serving and running models efficiently.
Context windowThe maximum number of tokens the model can consider at once.
Context engineeringChoosing, ordering and compressing what goes into the context.
Mixture of experts (MoE)Only part of the network runs for each token, giving a big model at lower cost.
DistillationTraining a small model to imitate a large one.
Speculative decodingA small model drafts tokens and the big model checks several at once, for speed.
EvalsTests that measure model quality on specific tasks.
Structured outputForcing the model's reply to match a schema, such as JSON.
LangGraphA library for building agents as graphs of steps.
Hugging Face TransformersThe most widely used library of pretrained models.
